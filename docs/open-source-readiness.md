## 整備したもの

- 初めて取得する人向けのREADME、詳しい使い方、開発参加案内、変更履歴。
- MITのLICENSEとpackageメタデータ、依存ライセンス一覧、バイナリ配布時の確認事項。

- Gitleaksによる全Git履歴・公開候補ファイルの秘密情報検査。バイナリは固定版とSHA-256を確認してローカル実行。
- Windows・Linuxの通常・ブラウザテスト、Windows・Mac（Apple Silicon・Intel）・Linuxのデスクトップのビルドと配布版テスト、依存ライセンス一覧・アイコン・秘密情報検査の自己テストを行うCI。2026-10-18にGitHub Actionsで成功。

- SQLiteの不要なネイティブビルドを避け、同梱バイナリを確認するセットアップコマンド。
- 配布版に同梱するライセンス原文、閲覧メニュー、欠落・改変を検出するパッケージ検査。
- 開発用を含む依存監査と、修正した旧ローダーの互換性テスト。本番依存は指摘0件を必須とし、修正版のない開発専用の指摘だけを期限付きの記録で許可。
- Windowsの導入・更新・削除・再導入を、専用のアプリ登録と架空データで確認するコマンド。

```sh
npm run setup
```

検査レポートは `.tmp/open-source/`、ブラウザ検証の成果物は `test-results/`・`playwright-report/` に保存します。これらを公開対象に含めません。秘密情報検査の「検出0件」は、未知の形式や画像の内容まで安全を保証するものではありません。

旧名称SideNote AIの2026-09-23の公開準備で、保存済みの配布物・バックアップ・検証記録と旧試作仕様書・引き継ぎメモを作業フォルダの外へ退避し、依存とビルド生成物を削除しました。開発再開時は `npm run setup` から実行します。今後の整理方法は [作業フォルダの容量を減らす](../CONTRIBUTING.md#作業フォルダの容量を減らす) を参照してください。以下にある過去の検証記録のパスは、検証時の保存先です。

## 公開用ソースZIP

公開対象の差分を確認してローカルでコミットした後、実行します。

```sh
npm run source:archive
```

`release/Fussenn-<version>-source-<commit>.zip` とSHA-256ファイルを作ります。ZIP内のフォルダは `Fussenn-<version>/` です。コミット済みHEADを対象に、`.git`・個人設定・会話DB・バックアップ・生成物・依存バイナリを含めません。未コミットの変更がある場合は停止します。GitHubへの送信はありません。

ローカルの過去のコミットには個人メールアドレスが含まれています。また、旧バックアップ画面にはPCのユーザーフォルダ名が写っていたため、公開候補の画像をデモ用データで撮り直しました。元の履歴を書き換えずに、新規公開リポジトリをZIPの内容から始める方法を用意しました。ZIPにはコミットハッシュがメタデータとして残りますが、コミットの作者名・メール・過去の画像・履歴は含みません。今後の公開用コミットには希望する作者名とGitHubのnoreplyメールを設定してください。元の履歴を公開する場合は別途確認が必要です。

## 公開する時に決めること

正式なプロジェクト名はFussennに決まりました。現在のMIT表記は `Fussenn contributors` です。

2026-10-18、ソースZIPの内容から新しい履歴で非公開のリポジトリを作り、コミットの作者にはGitHubのnoreplyメールを設定しました。残りは次のとおりです。

- リポジトリを公開に切り替える時期。公開リポジトリでは標準のrunnerによるCIが無料になり、デスクトップのビルドもプルリクエストで実行されます。
- GitHubのprivate vulnerability reportingを有効にして報告窓口を確認。必要に応じてブランチ保護・必須チェックを設定。
- 公開先が確定してから、READMEの取得先・リンク・リリース案内を更新。

## アプリの一般配布前に残ること

Apple Silicon Macでのビルド・配布版テスト・実機操作は確認済みです。Intel Macは、ビルドと配布版テストをGitHub ActionsとRosetta 2で確認済みで、画面を使った実機操作は未実施です。2026-11-08〜11に、Apple Silicon Macで、アプリとDMGのDeveloper IDによる署名とAppleの公証を確認しました。署名と公証は、指定したビルドでだけ行います。公証したアプリとDMGは、ダウンロード時と同じquarantine属性を付けても、Gatekeeperに許可されます。残るのは、実際にダウンロードしたDMGからの初回起動の画面確認、署名・公証したIntel版の確認、Windowsの署名です。署名しない成果物は、継承したad-hoc署名の厳密検証にも通りません。詳しくは [Macの検証記録](mac-validation.md) を参照してください。

ライセンス原文の同梱と検査を追加し、未使用のSharp/libvipsは新しいデスクトップ配布物から除外しました。依存や素材を更新した場合は [第三者のライセンス](../THIRD_PARTY_NOTICES.md) に従って再確認します。以前のインストーラーにはこの変更は適用されません。一般配布はまだ行っていません。

Windowsの導入・更新には [専用登録による自動テスト](windows-installer-test.md) を用意しました。配布用EXEそのものを、使い捨てのWindows環境でウィザード・ショートカットから操作する最終確認は別途必要です。

最初の実行では、Linuxのデスクトップだけが失敗しました。Next.jsのライセンス原文を `LICENSE.md` の名前で探していたためです。実際の名前は `license.md` で、大文字・小文字を区別しないMac・Windowsでは起きません。修正後は、大文字・小文字を区別するAPFSのディスクイメージ上でもprepare・pack・配布版テストが成功し、GitHub上のLinuxでも成功しました。

Windowsの起動・停止スクリプト、負荷検証、ショートカット、インストーラーの検証は通常のCIに含まれないため、検証用の一時ブランチで実行しました。runnerは英語版のWindows（文字コード1252）です。インストーラーの検証には中身の異なる2つのアプリが必要なため、同じコミットから2回ビルドし、古い方だけ `desktop/main.mjs` に1行のコメントを加えています。

Windowsの検証では、次の3つの問題が見つかり、修正しました。

- 負荷検証が、付箋一覧から開いた付箋へのメモ入力が保存されずに失敗しました。すでに開いている付箋では、一覧が閉じる前に入力していたためで、Macでも再現しました。一覧が閉じるのを待つようテストを直しています。アプリの動作は変わりません。
- インストーラーの検証が、日本語を含む導入先のショートカットを不一致と判定して失敗しました。ショートカットを読むWindowsの機能（WScript.Shell）が、システムの文字コードにない文字を「?」に変えていたためです。ブラウザ版のショートカット作成も同じ機能を使っており、英語版のWindowsなどで日本語を含むフォルダから作ると、起動できないショートカットになっていました。Unicodeを扱える機能に置き換え、両方を直しました。
- インストーラーの更新が、旧版を削除できずに失敗しました。配布版の内部サーバーが、表示したページのキャッシュをインストール先（`resources\server` の奥）へ書き込んでおり、検証用の長いインストール先では、そのパスが260文字を超えていました。electron-builderの更新処理は、旧版のファイルを一時フォルダへ移してから削除します。Process Monitorの記録では、約620ファイルを移した後に全体を元へ戻し、終了コード2で止まっていました。失敗した移動の呼び出しは記録されておらず、長すぎるパスをWindowsへ渡す前に扱えなかったものと見られます。サイレント実行では、エラーのダイアログを表示したまま止まります。キャッシュをメモリだけに置くと、同じ環境で更新を含む全段階が成功しました。同じキャッシュはMacでは `.app` の中に書かれ、署名済みアプリの内容を変えていました。配布版テストには、起動前と終了後でアプリのファイルが変わらないことの確認を追加しています。調査には、プロセスの一覧、全ファイルの移動の試行、Process Monitorによるアンインストーラーの記録を使いました。標準のインストール先（`%LOCALAPPDATA%\Programs\Fussenn`）はパスが短いため、多くの環境では起きにくい問題でした。

最後の確認では、WindowsのブラウザE2Eの1件が失敗しました。会話を開いた直後、読み込みが終わる前にメッセージ欄へ入力した文字が、読み込みの完了時に消えていたためです。読み込み中のメッセージ欄を読み取り専用にし、この順序を再現するブラウザテストを追加しました。修正と文書の更新を終えた最後のコミットで、2つのCIを改めて実行し、すべてのジョブの成功を確認しました。

非公開リポジトリでは、Macのrunnerの料金がLinuxの約10倍かかり、GitHub Freeでは成果物の保存容量が500MBまでです。このため非公開の間は、デスクトップのビルドをプルリクエストでは行わず、手動実行時だけ行います。テスト用の配布物は3日で削除する設定です。CIのログに、個人のメールアドレスやPCのユーザー名は含まれていません。
