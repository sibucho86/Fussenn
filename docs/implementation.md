## 設計の境界

- SQLiteが会話の正本。Drizzleのスキーマと、起動時のトランザクション内バージョン付きマイグレーションを使用。
- `messages` と `side_note_messages` は別テーブル。メインのContext Builderはメイン履歴だけを受け取る。
- 付箋のSnapshotは作成時にサーバーで生成し、クライアントから書き換えさせない。
- 付箋の意味的データと、Canvas基準の座標・寸法は別テーブル。
- Providerは正規化されたメッセージを受け取る。ブラウザには各SDK固有のイベントを公開しない。
- ローカルサーバーは127.0.0.1で待ち受ける。APIではHost / Originも検証する。
- APIキーは環境変数のみ。Codex認証はCodex自身に委譲する。

## 確認資料

- [Codex App Server公式ドキュメント](https://developers.openai.com/codex/app-server)
- ローカルのCodex CLI 0.144.4で `codex app-server generate-ts` により生成した安定APIの型。

公式ドキュメントとインストール済みCLIにはread accessの型に差がある。read-only sandboxに加え、Fussenn専用cwdとツール無効化を使用する。OSごとの隔離動作にはCLI側の制約がある。

Codexの設定はテーブル単位でマージされるため、`mcp_servers = {}` だけでは既存サーバーを無効化できない。初期化時に `config/read` で既存の名前を取得し、FussennのThreadに限って各 `enabled` をfalseにする。ユーザーの設定ファイルは変更しない。CLI 0.144.4は `sandboxPolicy.access` に未対応のため、同CLIの安定APIに合わせてread-onlyとnetworkAccess=falseを指定する。

## 追加機能: マーカーに付箋をしまう

## 追加機能: 曲線の引き出し線とマウスでの調整

引き出し線は1本の3次ベジェ曲線で描画する。複数行のマーカーと付箋の各辺から候補を作り、線の長さ、接続方向、本文・別の付箋との交差を比較して接続を自動選択する。ヘッダーの曲線アイコンで調整モードに入り、線そのものや中央のハンドルをドラッグするとカーブを変更できる。両端のハンドルはマーカー・付箋の最寄りの辺に吸着し、上下左右の接続位置を変更できる。

接続位置は辺・辺内の比率・マーカーの行番号、カーブは自動形状からの変位として保存するため、付箋の移動・サイズ変更・折りたたみに追従する。中央の変位に応じて2つの制御点を動かし、線の途中を掴んだ場合は掴んだ場所がマウスに追従するよう補正する。DB version 5で nullable な `side_note_layouts.connector_json` を追加し、既存の付箋は自動配置のままにする。APIは辺・比率・変位の範囲と構造を検証する。

ドラッグ中は即時プレビューし、マウスを離すと保存する。Escやポインターキャンセルで操作前に戻り、保存失敗時も元の形に戻してエラーを表示する。矢印キー・Shiftでの調整、自動配置へのリセット、調整モードの終了に対応する。調整用ツールバーはCanvasのスクロール位置を考慮して表示領域内に収める。通常時の線はポインターを透過して文字選択を妨げない。

本文の描画済みテキスト矩形を計測し、SVGマスクで文字の周囲2pxを非表示にする。経路計算は `src/lib/connector.ts`、編集UIは `src/components/sidenote/editable-connector.tsx` に分離し、DOMの再計測は本文・アンカー・表示サイズの変化に限定する。マーカー収納中は線と編集UIも非表示にする。

自動接続・カーブ変位・接続比率の追従・複数行と再折り返し・DB移行と保存をユニット／結合テストで検証。ブラウザでは線と両端のドラッグ、保存・再読み込み、移動・折りたたみ、リセット、Esc、キーボード、保存失敗と再試行、API入力検証を確認する。`docs/connector-edit.png` が調整中、`docs/connector-curve.png` が通常表示の画面。

## 追加機能: 会話内の付箋一覧

ヘッダーの付箋数を「付箋一覧」ボタンに変更。右側に一時的な一覧ダイアログを開き、現在の会話の付箋だけを作成順で表示する。各項目に色・選択した言葉・メモまたは最新の付箋回答の抜粋・表示状態を表示する。元の言葉・メモ・付箋メッセージ全体を検索でき、NFKC正規化と大文字・小文字の統一、空白区切りのAND検索に対応する。「しまった付箋」でマーカー収納中の項目に絞り込める。

一覧を開いてもCanvasの幅と付箋のコンポーネントを維持するため、付箋の位置・アンカー・入力中の質問・生成処理が保持される。項目を選ぶとレイアウトの既存APIで収納・折りたたみを解除し、前面に出してスクロールとキーボードフォーカスを移動する。保存が失敗した場合は一覧を開いたまま再試行できる。内容・Snapshot・色・座標・サイズ・曲線調整を書き換えない。DB・APIスキーマの変更はない。

一覧は現在の会話のReact stateを参照し、編集・生成・追加・削除を反映する。ネイティブdialogによるフォーカス制御、検索欄への初期フォーカス、Esc・外側クリック・閉じるボタンに対応する。会話を切り替えると一覧を閉じ、検索・絞り込み状態をリセットする。再表示時のフォーカス移動は、ダイアログが閉じた後のフレームで行う。

E2Eで一覧・検索・色と表示状態・収納／折りたたみからの移動・元データと入力途中の質問の保持・編集と削除の反映・再読み込み・復元の失敗と再試行・キーボード・会話ごとの分離・空の一覧を確認済み。実際のブラウザ画面は `docs/note-index.png`。

## 追加機能: ドラッグ＆ドロップで会話を整理

サイドバーの会話タイトルをネイティブHTML Drag and Dropでつかみ、フォルダまたは未分類へドロップできる。ドラッグ中は移動可能なフォルダを枠で示し、カーソルを重ねた移動先をハイライトする。フォルダ見出しとその中の領域をドロップ先として扱い、空・折りたたみ中のフォルダにも対応する。保存後に移動先を展開する。同じ保存先へのドロップはAPIを呼ばず、Escや対象外へのドロップで終了する。

既存の会話PATCH APIに `folderId` のみを送る。保存完了まで表示上の所属を維持し、処理中の二重移動を防ぐ。失敗時は元の場所に表示を残して再試行を提示する。専用のMIME型と同じサイドバーで開始したドラッグのIDを照合し、外部のテキストやファイルを会話として扱わない。依存パッケージ・DB・APIスキーマの追加はない。

移動結果は保存先と更新時刻だけをReact stateへ反映し、タイトルや生成中の会話、付箋、入力途中の文章を置き換えない。ドラッグと通常クリックを区別し、整理だけで別の会話へ切り替わることを防ぐ。従来の「…」編集画面によるフォルダ選択も維持する。

E2Eでは実際のマウスによる閉じたフォルダ・フォルダ間・未分類への移動、ハイライト、再読み込み、同じフォルダへのドロップ、会話と付箋・入力の保持、保存中と失敗時の表示・再試行、部分的なメタデータ更新、Esc、対象外のドロップ、通常クリックを確認済み。ドラッグ中の画面は `docs/folder-drag.png`。

## 追加機能: 全付箋の引き出し線と一括表示切り替え

選択中の付箋に限定していた引き出し線を、表示中の全付箋へ拡張した。会話を開いた直後や選択が変わったときも各付箋の色で表示し、選択中の線は少し太くする。折りたたんだ付箋にも接続し、マーカー収納中の付箋には線を出さない。原文を復元できない場合や自動接続の元マーカーが付箋自体で覆われている場合の扱いは従来どおり。

名称変更時、デスクトップ版は独自URLが `fussenn://app/` になり、画面状態の保存場所も変わるため、引き出し線の表示切替と原稿の表示モードが一度だけ初期値に戻る。ブラウザ版は旧キーから引き継ぐ。

E2Eで選択前からの複数線表示、選択切り替え・移動・折りたたみへの追従、収納・復元・削除、色と接続点、個別編集、一括表示切り替えと再読み込み・会話切り替え、データ保持、文字選択を確認済み。俯瞰したブラウザ画面は `docs/connector-overview.png`。`npm run check`（lint・型検査・39テスト・本番ビルド）とPlaywright全19シナリオが成功。起動中のアプリを更新し、既存の会話・付箋・メッセージ・フォルダが再起動前後で変わっていないことも確認した。

## 追加機能: Obsidian用MarkdownのZIP書き出し

右上の **MD保存** で、開いている会話と全付箋を相互リンク付きMarkdownとしてダウンロードする。ZIPの中には会話IDごとのフォルダと、会話のMD、付箋ごとのMD、取り込み手順のテキストを含む。保管庫内の任意のフォルダへ配置でき、追加プラグインは不要。

現在のフォルダ名は `Fussenn-<id>`、ZIP名は `Fussenn-<タイトル>-<id>.zip`。プロパティは `fussenn_type`・`fussenn_id`、発言のアンカーは `^fussenn-message-<id>` とする。名称変更前の書き出しは `sidenote_type`・`sidenote_id` を使っており、既存の書き出しは変更しない。

`src/lib/obsidian-export.ts` で文書を生成する。会話には全発言・付箋一覧・発言ごとの付箋リンク、各付箋には元の選択文の引用・メモ・付箋内の全発言・元の発言へ戻るブロックリンクを含む。ブロックIDは発言IDから作り、該当する発言の日時行に付ける。本文のMarkdownは保持し、未完了のコードフェンスは閉じて後続の発言やリンクがコードに取り込まれることを防ぐ。生成中・中断状態を明記し、収納・折りたたみ中の付箋も収録する。元の発言がない場合は引用文を保持し、会話全体へのリンクを出す。

ファイル名は日本語を残しつつWindowsとObsidianで問題になる文字を除き、短いタイトルと完全なIDを組み合わせて重複を防ぐ。ZIP内は会話IDのフォルダ1階層だけとし、相互リンクは一意なファイル名を使う。YAML frontmatterにはJSON互換の引用でタイトル・日時・色などを記録する。ProviderのセッションID・ContextSnapshot・座標などを出力へ流用しない。外部の画像や添付ファイルの取得、再取り込み・同期は対象外。

`conversation-export.tsx` はクリック時点の画面データを複製してから変換モジュールを遅延ロードする。保存前のメモを含め、別の会話への切り替えや後続の生成更新で書き出し内容が変わることを防ぐ。未送信の質問は含めない。ZIPの作成は [fflate](https://github.com/101arrowz/fflate) の非同期APIを使い、大きなファイルはブラウザのWorkerで圧縮する。Object URLでダウンロードを開始し、遅延してURLを解放する。処理中の重複実行を防ぎ、失敗時は同じボタンで再試行できる。案内は閉じられ、再試行後は古いエラーを残さない。DB・API・AI Providerへの変更はない。

## 追加機能: Markdown・テキスト資料の取り込み

サイドバーの **資料を開く** と開始画面の **手元のMarkdown・テキストを開く** から、ローカルの `.md`・`.markdown`・`.txt` を取り込む。ファイル選択とドロップに対応し、冒頭を確認して保存する。UTF-8のBOMを除去し、不正なUTF-8・空白のみ・制御文字を含むバイナリ・1MB超のファイル・10万文字超の本文・対象外の拡張子を拒否する。取り込み時はAIを呼ばない。失敗時はファイルの内容を保持して再試行でき、キャンセルでは開いていた会話や下書きを維持する。

DB version 6で `document_sources` を追加する。既存の会話・付箋・本文テーブルは書き換えず、会話IDと元本文のメッセージID、ファイル名、形式を関連付ける。資料本文は利用者が持ち込んだ参照データとして `messages` に1件の `user` 行で保存し、画面と書き出しでは会話の発言として扱わない。資料画面は元ファイル名・形式・取り込み日・読み取り専用を表示し、Markdownは既存の安全な描画コンポーネント、テキストはエスケープされた文字列と改行を表示する。本文を更新するAPIはなく、資料へのメイン会話送信も拒否する。ファイル名をパスとして使わず、元のファイルは変更しない。

資料の本文もアンカーを持つため、既存の付箋のメモ・色・移動・折りたたみ・収納・一覧・引き出し線を共用する。付箋を作るときに、資料の全文と選択箇所、元ファイル名・形式・参照範囲をContextSnapshotへ固定する。AIへは資料の参照データとして渡し、資料内の文を指示として扱わないよう区切る。他の資料・別の付箋・未送信の入力は含めない。画面にも参照範囲を表示し、本文を黙って切り詰めない。Provider・モデル側の容量を超えた場合は既存の生成エラーとして表示する。

読む・メモする操作にはAI設定を要求しない。初期Provider・モデルは取り込み時点のアプリ設定を引き継ぎ、資料上部の **付箋AIの設定** で変更できる。変更時にProviderのセッションIDを解除し、次の質問は保存済みの資料と付箋内の会話から再構成する。生成中は変更を拒否し、設定更新時に画面のメモ下書きや位置を置き換えない。資料のタイトル変更・フォルダへの移動・削除は既存の整理機能を共用する。

Obsidian書き出しでは、資料用のMDに元ファイル名・形式・本文を残し、付箋から **元の資料へ戻る** リンクを出す。テキスト形式はフェンスの長さを調整したコードブロックとして収録するため、Markdown記号を含んでも原文を文字どおり読める。同名の再取り込みは独立した資料で、元ファイルの同期、本文編集、画像や添付ファイル、書き出した付箋の再取り込みは対象外。

テストではv5からのデータ保持、資料の保存と再オープン、AI参照の分離、読み取り専用、Provider設定の変更とセッション解除、資料用MDの相互リンク、日本語ファイルと不正な入力を確認済み。ブラウザでは実ファイル取り込み、実際の文字選択、付箋とAIへの質問、収納・一覧・復元、書き出し、同名ファイルの分離、タイトル・フォルダ整理・削除、キャンセル・再試行、AI未設定からの利用と生成中の設定変更拒否を確認済み。画面は `docs/imported-document.png`。
