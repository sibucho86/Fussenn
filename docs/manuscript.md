# 原稿編集（v0.2）

サイドバーの「原稿を書く」では、「白紙から始める」と「ファイルから取り込む」を選べます。ファイルは `.md`・`.markdown`・`.txt` に対応し、ファイル選択またはドラッグ＆ドロップで読み込みます。ファイル名を元にタイトルを設定し、本文プレビューを確認して「原稿として取り込む」を押すと、直接編集できる原稿を作成します。タイトルは変更できます。

UTF-8の1MB・10万文字以内のファイルを、一つずつ取り込めます。本文はFussenn内にコピーして保存するため、元ファイルを移動・削除しても原稿は残ります。元ファイルへの書き戻しや同期は行いません。Markdown・テキストともMarkdown原稿の編集画面で開き、改行はLFに揃えます。取り込み時の本文は最初の版として履歴に残ります。取り込みだけではAIに送信しません。

既に取り込んだ資料やAIの回答の「原稿として編集」からも、本文をコピーして独立した原稿を作れます。元の会話・資料・付箋は保持します。一章ずつ作り、既存のフォルダでまとめる使い方を想定しています。

## 書く・推敲する

原稿上部の「編集」「並べて表示」「プレビュー」でMarkdownの編集と整形表示を切り替えられます。「目次」から見出しへ移動でき、本文と選択範囲の文字数も表示します。操作の詳細は [原稿のプレビュー](manuscript-preview.md) を参照してください。

本文はMarkdownを直接入力するエディタです。日本語の変換入力、貼り付け、通常の取り消し・やり直しに対応します。本文の選択後に「＋付箋」を押すか、ツールバーの「選択箇所・カーソルに付箋」を使います。何も選択していなければ、カーソル位置への挿入用付箋になります。

付箋でAIと相談し、回答の「原稿案に使う」で文章を原稿案の編集欄へ移せます。この欄は手入力でも編集できます。「本文へ反映…」で置換・直前への挿入・直後への挿入を選択し、削除部分と追加部分を確認して反映します。挿入時に空白や改行を自動追加しないため、必要な改行も原稿案に含めてください。

反映後も付箋は開いたままです。「続けて推敲する」を押すと、同じ付箋で反映後の文章から次の原稿案を作れます。反映済みの付箋からAIに追加質問を送った場合も、先に推敲を再開します。修正後の原稿全文と現在の対象箇所をAIへ渡し、原稿案の欄には現在の対象文章を入れます。AI回答の「原稿案に使う」や手入力で案を調整し、差分を確認して再び反映できます。挿入した場合は、挿入した文章が次の推敲対象です。不要なときは「マーカーにしまう」で収納できます。

推敲を再開しても過去の本文の版・相談履歴・AI参照Snapshotは残ります。以前の相談は記録として残し、次のAIへの送信は更新後の本文から始めます。同じ案の二重反映や古い画面からの上書きは拒否します。対象箇所を直接編集して紐づきが解除されている場合は、本文を選び直して付箋を作ってください。

## AIが参照する本文

- 新しい付箋を作る前に、入力中の原稿を保存します。付箋には、その版の原稿全文と選択箇所のSnapshotをサーバー側で保存します。
- 保存できない場合や、別の画面で原稿が更新されている場合は、付箋を作成せずエラーを表示します。
- 既存の付箋は作成時の参照を保持し、「AI参照：版 N」と表示します。
- 「最新の本文で相談し直す」では、現在の本文と付箋の現在位置を参照し直します。以前の会話は画面に残し、古い参照Snapshotも保存します。Providerセッションを解除し、以後のAIへの送信には参照更新後の相談だけを含めます。
- 他の原稿や別の付箋の会話は自動では含めません。参照は一つの原稿全文です。モデルの容量を超えた場合、既存の生成エラーとして表示し、黙って切り詰めません。

## 保存・履歴・復元

本文は入力が約1秒止まったとき、原稿案は約0.7秒止まったときに自動保存します。付箋作成・反映・履歴表示・会話移動・デスクトップの終了前にも保存します。日本語変換が未確定の場合は操作を見送り、確定後に再試行できます。

「履歴」で保存した各版を確認できます。「初稿」「編集者提出前」などの名前を付けた保存もできます。過去版を復元すると、その本文と当時の付箋の紐づきを新しい版として保存するため、復元操作も取り消せます。付箋の会話や原稿案は消しません。復元先の版に存在しなかった付箋は、引用を保持して紐づきがない状態にします。

本文を編集した場合、範囲の手前の変更には付箋が追従します。範囲内を直接変更した場合は紐づきを解除し、元の引用を残します。同じ文章が別の場所にあっても自動で付け替えません。本文全体の履歴復元で、当時の紐づきに戻せます。

保存失敗時は本文と原稿案を画面に保持し、再試行できます。本文は「手元の編集をMDに退避」から書き出せます。古い画面による上書きは原稿の版番号・原稿案の版番号で拒否します。通常の会話移動とデスクトップ終了は保存失敗時に見送ります。強制終了・OS停止時の未保存入力の保持までは保証しません。

## データと書き出し

正本は既存のSQLiteです。Gitのインストールは不要です。DB v9で資料に編集可否・現在の版番号を加え、`manuscript_notes` と `manuscript_revisions` を追加します。既存の資料は読み取り専用のままです。本文・付箋の紐づき・反映状態・原稿履歴を一つのトランザクションで保存します。

「MD保存」のObsidian用ZIPには最新の原稿と全付箋、原稿案、参照版・反映状態を収録します。原稿の全履歴と過去の参照Snapshotは、設定の完全バックアップに収録します。現在はv3の `.fussenn.json` を書き出し、名称変更前の `.sidenote.json` とv1・v2の読み込みにも対応します。v1・v2のみ対応する版ではv3のバックアップを復元できません。形式と互換対応は [バックアップと復元](backup-restore.md) を参照してください。

原稿は一つにつき10万文字、選択範囲・原稿案は2万文字まで。履歴は自動削除せず、各版の本文を保存するため容量が増えます。完全バックアップの上限は従来の64MBです。複数人の同時編集、章をまたぐAI参照、縦書き、組版、Git同期は含みません。

## 画面設計

既存の紙色 `#faf9f6`、本文 `#303731`、ナビゲーション `#f1f2eb`、編集操作の緑 `#435e47`、付箋 `#fff5c6` を継承します。日本語の本文にはYu Gothic / Hiragino、操作には既存のSegoe UI系を使い、本文を左、付箋を右に配置します。本文の行長を抑え、変更プレビューで削除と挿入を色と取り消し線・下線の両方で示します。

エディタはCodeMirror 6、差分計算はjsdiffを使用。描画済みMarkdownの位置と編集ソースの位置を混同せず、原稿ではUTF-16の編集位置で付箋を管理します。表示中の範囲をエディタのDOM位置に対応させて、既存のマーカー・引き出し線・付箋キャンバスを共用します。
