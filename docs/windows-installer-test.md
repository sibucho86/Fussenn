# Windowsインストーラーの導入・更新テスト

`npm run test:desktop:installer` は、2つのFussennインストーラーからアプリ本体を取り出し、検証専用のNSISインストーラーに包み直して導入・更新・削除を実行します。Windows x64用です。

普段のインストールと衝突しないよう、実行ごとにアプリID・登録用GUID・EXE名・ショートカット名・インストーラーキャッシュを変えます。アプリ本体のバイト列は保持し、EXEのファイル名だけを変えます。保存先は専用の一時フォルダに固定し、架空の会話と原稿、Mockプロバイダーで検証します。

## 実行

`npm run setup` 済みの作業フォルダで、ライセンス文書を同梱したFussennの新旧2つのWindowsインストーラーを指定します。最新版は作業フォルダの製品情報・アイコンに一致する必要があります。2つのインストーラーは、アプリ本体に加えて、同梱のNode.js・サーバーのビルド・Electronの違いでも区別するため、依存だけを更新したビルドどうしも検証できます。古いファイルを残してから新しいビルドを作ってください。

検証スクリプトは保存先の環境変数を新旧両方の名前で渡すため、名称変更前のSideNote AIを誤って指定しても、検証専用の保存先を使います。ただし独自URL・ヘッダー・DB名はFussennの名前を前提にしているため、名称変更をまたぐ更新の検証には対応していません。両方とも名称変更後のビルドを指定してください。

```powershell
npm run test:desktop:installer -- --previous 'C:\builds\previous.exe' --current 'C:\builds\current.exe'
```

一時的に `Fussenn-Test-…` というアプリ・ショートカットが作られ、検証用ウィンドウが開きます。各インストーラーは5分で打ち切ります。electron-builderのインストーラーは、更新時に旧版を削除できないと、サイレント実行でもエラーのダイアログを表示したまま止まるためです。テスト成功後に、専用のインストール・登録・ショートカット・キャッシュ・データを片付けます。失敗した場合は専用フォルダを残し、場所を出力します。上記の名称変更後のビルドを使う手順には、普段のFussennを削除するコマンドや、実利用のDBを開く処理は含みません。

NSISの導入方式・データ削除設定・アイコンは、配布ビルドと共通の `scripts/desktop-installer-options.mjs` を使います。テスト用の表示バージョン `0.0.1` → `0.0.2` は更新処理を動かすためのラベルです。Fussennの過去リリース番号やDB移行テストを意味しません。

## 確認すること

1. 日本語と空白を含む指定先へ、ユーザー単位で新規インストールできる。
2. デスクトップ・スタートメニューのショートカットが、正しいEXEとアイコンを参照する。
3. インストールされたEXEが起動し、会話・フォルダ・資料・色付き付箋・原稿・原稿案の反映履歴・設定を保存できる。
4. 更新時に指定先を省略しても、以前の導入先が使われ、新しいアプリ本体へ置き換わる。
5. 更新と同じバージョンの再インストールで、保存データ全体・原稿履歴・localStorageの保存値が引き継がれる。
6. アンインストールでアプリ・登録・ショートカットが消え、DBのバイト列がそのまま残る。
7. 再インストールして、残したデータを再び画面に表示できる。

各段階で、普段のFussennと旧SideNote AIのEXE、登録情報、ショートカットに変化がないことも照合します。検証結果と架空データのスクリーンショットは `test-results/installer/<ID>/` に保存します。このフォルダはGitの対象外で、結果にはPC内の絶対パスが含まれるため、そのまま公開資料へコピーしないでください。

## 検証範囲

このテストは、アプリ本体を保った検証専用インストーラーを `/S /currentuser` で動かす自動検証です。配布用EXEそのものを現在のユーザー環境へインストールする処理ではありません。

配布直前には、実利用のアプリやデータがない使い捨てのWindows環境で、配布用EXEそのものについて次を確認します。

- ウィザードの表示、導入先の選択、完了後の起動、実際のショートカットからの起動。
- 以前の配布用EXEで架空データを作り、新しい配布用EXEへ更新して引き継ぎを確認。
- Windowsの「インストールされているアプリ」から削除し、再導入してデータ保持を確認。
- 配布用の製品名・登録用GUID・ショートカット名での動作、署名やSmartScreenの表示。

自動テストだけで、ウィザードの手動操作、全ユーザーへのインストール、実在する旧スキーマからの移行、Macの動作を確認したことにはしません。
