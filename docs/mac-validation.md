# Macの検証記録

検証結果と成果物は、旧名称SideNote AIのときの記録です。再現手順は現行のFussennに合わせています。

2026-09-22〜23、Apple Silicon（arm64）・macOS 26.6.2で、ブラウザ版とMacデスクトップ版を検証しました。Mac用DMG・ZIPを生成し、展開したアプリの自動テストとネイティブ画面の操作を確認しました。正式な署名・公証は未設定で、一般配布の準備完了とは扱いません。

## 環境と確認方法

- 対象は `e7ce20b01f8985ed80c753eaa4ab430d85a5d753` と、今回の検証で修正したファイル。修正は検証後にコミットしました。
- Node.js 24.15.0 / npm 11.12.1 / Electron 44.3.0。Nodeは公式のmacOS arm64配布アーカイブを取得し、公式のSHA-256一覧と照合しました。普段のNode.js 26.0.0の設定は変更していません。
- ソースを作業フォルダ外へコピーし、既存の依存・環境ファイル・生成物を持ち込まずに `npm run setup` を実行しました。元フォルダのWindows用 `.desktop` は再利用していません。
- AI生成はMock、保存内容は合成した検証用データです。実AIへの生成要求、ログイン・ログアウト、既存の認証情報の変更は行っていません。
- 自動テストは専用の一時データを使用します。実機操作の起動時には、検証ツールが設定する `ELECTRON_RUN_AS_NODE` を除去したうえで、最小限のPATHと専用保存先を指定しています。
- 最初の実機操作ではGUIからの起動によって標準保存先が新規作成されました。作成時刻と唯一の会話が検証用原稿であることを確認して、フォルダ全体を専用保存先へ移しました。標準保存先は元の未作成状態に戻しており、既存の利用データはありませんでした。
- 容量不足で一度中断しましたが、容量確保後に再開しています。ログ・検査JSON・失敗時のtraceは検証時に `.tmp/mac-validation/` へ保存し、公開準備の整理で作業フォルダ外へ退避しました。生成したスクリーンショットで既存の公開用画像を上書きしていません。

## 見つかった問題と修正

1. 引き出し線の編集ツールバーが端点のハンドルに重なり、マウス操作を受け取っていました。ツールバーの実寸を計測し、3つのハンドルを避けて表示領域内に配置するよう修正しました。ドラッグ操作と期待値を変えず、既存E2Eが成功しました。画面も目視確認しています。
2. 付箋一覧のE2Eで、1枚目の保存完了前に2枚目を選択していました。各付箋の表示完了を待つよう修正しました。
3. 原稿プレビューのE2Eで、編集欄にフォーカスが移る前に入力していました。フォーカスを待つよう修正しました。
4. Macの保存ダイアログをキャンセルしても「書き出しました」と表示されました。通知を「ZIPを用意しました。保存したZIPを展開し…」へ変更し、ファイル保存の完了を断言しないようにしました。

Mac専用の自動テスト2件を追加しました。最小限のPATH、Mac編集キーとUndo/Redo、ウィンドウ終了時の保存、子サーバー終了、再起動後の本文保持、アプリメニューのネイティブ終了アクションを確認します。

最初のCmd+Q自動テストはタイムアウトしました。Playwrightのキー入力とElectronの `sendInputEvent` はrendererへ届きますが、Macのネイティブメニューのショートカットは発火しませんでした。そのため自動テストの名称・操作を実際の確認範囲に合わせ、Cmd+Qは別途実キーで検証しています。

## 現行版の再現手順

Node.js 24.15.0を使用し、次を順に実行します。prepare・pack・配布版テスト・distは同じ生成先を使うため並行実行しません。

```sh
npm run setup
npm run desktop:prepare
npm run desktop:pack
npm run test:desktop:packaged
npm run desktop:dist
```

現行版の配布物は `Fussenn-<version>-mac-arm64.dmg`・`Fussenn-<version>-mac-arm64.zip`、アプリは `Fussenn.app` です。DMG/ZIP生成後は、展開した `Fussenn.app/Contents/MacOS/Fussenn` を `FUSSENN_DESKTOP_EXE` に指定して `npm run test:desktop` を実行します。テストは保存先を分離します。ネイティブ画面を別途確認するときも、検証用の `FUSSENN_DATA_DIR` を指定してください。
